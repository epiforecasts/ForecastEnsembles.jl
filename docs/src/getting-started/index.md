# [Getting started](@id getting-started)

`ForecastEnsembles.jl` combines several probabilistic forecasts of the same
target into one. Everything works on a [`ForecastTable`](@ref), a long-format
frame aligned with the hubverse `model_out_tbl` schema, and every method is
applied with one of two verbs: `combine` to aggregate, `fit` to estimate
weights from past performance first.

## Combine three forecasts

Wrap the component forecasts and take an equal-weight quantile mean, the
combination a hub reaches for first:

```@example getting-started
using ForecastEnsembles, DataFrames

df = DataFrame(
    location = "A", horizon = 1,
    model_id = repeat(["m1", "m2", "m3"], inner = 2),
    output_type = "quantile",
    output_type_id = repeat([0.25, 0.75], 3),
    value = [1.0, 3.0, 2.0, 4.0, 0.5, 2.5]
)

ft = ForecastTable(df; task_id_cols = [:location, :horizon])
combine(ft, QuantileEnsemble(:mean))
```

The task-id columns say what identifies a single forecast target: here one
location at one horizon. Models are combined within each of those groups.

## Next: choose how to weight

Equal weights are the default, not a requirement. Weights can be supplied
directly:

```@example getting-started
w = EnsembleWeights(DataFrame(
    model_id = ["m1", "m2", "m3"],
    weight = [0.5, 0.3, 0.2]
))

combine(ft, MixtureEnsemble(; weights = w))
```

Note this also swapped the combination operation. `QuantileEnsemble` averages
quantile values at each level; `MixtureEnsemble` averages the distributions
themselves. They give different answers, and choosing between them is the first
of the two decisions the [Methods](@ref) page sets out.

## Next: estimate weights from past forecasts

Where past forecasts and observations are available, weights can be estimated
rather than chosen, by minimising a score on that history:

```julia
fitted = fit(CRPSStacking(), training_forecasts, observations)
combine(ft, MixtureEnsemble(; weights = fitted))
```

[`CRPSStacking`](@ref) and [`QRA`](@ref) work on quantile forecasts; the
score-driven estimators take a scoring function you supply and need sample
forecasts. The [worked example](../example.md) runs all of them on a real
hubverse slice.
